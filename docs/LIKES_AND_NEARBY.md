# 좋아요와 주변 출사 (최종 갱신: 2026-10-07)

## 구현

- 메인 탭: 리스트 / 내 주변 출사 보기. 리스트는 업로드 최신순 또는 좋아요 인기순(동점이면 업로드 최신순).
- 메인 카드와 공개 글보기에서 비회원 좋아요 설정/취소. 서버 응답이 성공한 뒤에만 숫자와 상태를 변경한다.
- 글별 IP 하나당 한 표. IP 원문은 애플리케이션 DB에 저장하지 않고 서버 비밀키를 사용하는 게시글별 HMAC-SHA256 값으로 구분한다. IPv6 표기 차이와 IPv4-mapped IPv6는 정규화한다.
- 서버 트랜잭션으로 표와 총수를 함께 변경하며 같은 상태 재요청은 멱등 처리한다. 상태 변경은 같은 글/IP에서 1초 간격이다.
- 공개 글만 집계 가능. 집계/표 컬렉션은 브라우저에서 직접 읽거나 변경할 수 없다. API는 IP별 응답을 캐시하지 않는다.
- 주변 출사 탭에서 별도 위치 사용 안내를 먼저 표시하고, 동의한 경우에만 브라우저 위치 권한을 요청한다. 거절/Esc 시 지구 전체보기로 이동한다.
- 현재 위치는 컴포넌트 메모리에서만 거리 계산에 쓰며 새로고침/탭 이탈 시 사라진다. 서비스 서버로 좌표를 전송하지 않는다. 지도 제공자는 표시 지역 타일 요청과 접속 정보를 받는다.
- 기본 반경 50km, 10/25/50/100/200km 선택. 직선거리 가까운 순서. 공개 위치가 없거나 위치 공유를 끈 글, 예시 좌표는 제외한다.
- 일반 회원의 가입/글 작성/사진 업로드는 Google 로그인(`firebase.sign_in_provider == 'google.com'`) + 이메일 인증 + 기존 가입 상태 검사를 모두 통과해야 한다. 기존 관리자 계정 방식은 유지한다.

## 공개 프로필·댓글 통합 상태

- 공개 글보기 화면에는 좋아요, 신고, 댓글이 함께 표시되고 작성자 UID가 있는 회원 글은 공개 프로필로 이동할 수 있다.
- 좋아요는 기존처럼 비회원 IP 기준이며, 댓글 작성은 가입을 완료한 Google 회원 기준이다. 두 기능은 서로의 상태나 식별자를 공유하지 않는다.
- 위치를 비공개로 전환해도 댓글에는 위치 좌표가 자동 추가되지 않는다. 이용자가 댓글 본문에 직접 작성한 장소 정보는 자동 제거하지 않는다.
- 게시글 삭제 시 댓글 하위 문서는 함께 정리한다. 좋아요 집계와 투표 기록은 서버 전용 데이터이므로 기존 문서에 적힌 별도 정리 작업이 여전히 필요하다.
- 공개 프로필·댓글 규칙과 탈퇴용 댓글 인덱스는 로컬 코드에 반영했으며 운영 Firebase에는 아직 배포하지 않았다.

## 실제 좋아요 활성화에 필요한 서버 설정

현재 운영정보/정책 확정과 회원 개방은 보류 상태다. Google 제공자를 Console에서 켜는 것만으로 서버 좋아요 권한이나 회원 오픈 설정이 완료되지는 않는다.

1. Next.js 서버 런타임에 Firebase Admin 자격 증명을 제공한다. Google 환경에서는 Application Default Credentials를 권장한다. 다른 환경은 비밀 환경변수 `FIREBASE_ADMIN_SERVICE_ACCOUNT`에 서비스 계정 JSON을 설정할 수 있다. 브라우저용 `NEXT_PUBLIC_*`에는 절대 넣지 않는다. 선택적으로 `FIREBASE_ADMIN_PROJECT_ID`를 지정한다(기본은 기존 Firebase 프로젝트).
2. 충분히 무작위인 32자 이상 비밀값을 서버 전용 `LIKES_IP_SECRET`으로 설정한다. 서버 인스턴스마다 동일한 값을 쓰고 유지해야 기존 좋아요 식별이 유지된다. 키를 바꾸면 중복 표 방지 기록의 연결이 끊기므로 별도 마이그레이션 없이 회전하지 않는다.
3. `LIKES_TRUSTED_IP_HEADER`를 배포 프록시가 **사용자 입력을 덮어쓰는 단일 IP 헤더**로 지정한다. 프록시 외부에서 원본 서버에 직접 접근하지 못해야 한다. 여러 IP를 포함한 전달 체인은 거부하며 임의로 첫 IP를 신뢰하지 않는다. Vercel의 직접 배포는 공식 요청 헤더 문서를 확인해 설정한다. 로컬 개발에서는 헤더 미설정 시 localhost 요청만 127.0.0.1로 취급한다.
4. 수정된 Firestore/Storage 규칙을 검토·배포하고 `LIKES_ENABLED=true`를 설정한다. 환경변수 누락/연결 오류 시 버튼은 비활성 상태와 안내를 표시하며 0표로 가장하지 않는다.
5. `voters` 컬렉션 그룹의 `expiresAt`에 Firestore TTL을 설정하면 취소 기록이 약 하루 후 자동 정리된다. 활성 표에는 TTL이 없다. 게시글 삭제 시 관련 likeStats/likeVotes 서버 정리 작업도 운영 작업에 포함해야 한다(현재 글 삭제는 이 서버 전용 데이터까지 정리하지 않는다).

서버 설정값은 이번 작업에서 생성하거나 운영 환경에 배포하지 않았다.

## 한계와 출시 전 후속 항목

- 같은 와이파이/공유기/통신사 공인 IP를 쓰면 한 표를 공유하며, VPN·모바일망 전환·IPv6 주소 변경은 별도 표가 될 수 있다. IP 기반 방식으로 '사람당 한 표'를 보장할 수 없다.
- 회원 여부와 관계없이 IP별 상태를 반환하므로 같은 네트워크 사용자는 같은 좋아요 상태를 볼 수 있다.
- 전체 요청량 제한/WAF/App Check 등은 별도다. 현재 쿨다운은 글별 상태 변경 중복 억제이며 전체 서비스에 대한 봇/비용 방어를 대체하지 않는다.
- Google 가입은 무분별한 업로드를 줄이는 첫 단계다. 기존 글당 12장 제한 외에 서버에서 일별 업로드 건수/총 저장량을 강제하는 장치가 필요하다. 현재 서브컬렉션 직접 쓰기까지 총 업로드량을 강제하지 않는다.
- IP 원문은 인프라 액세스 로그에 남을 수 있다. 공개 전 실제 로그·HMAC 표의 보관/삭제 정책, 제공자, 위치 처리 안내를 개인정보처리방침에 확정해야 한다. 이번 작업은 정책 확정을 대신하지 않는다.
- 목록은 기존 방식대로 공개 글을 불러와 브라우저에서 정렬/거리 계산한다. 대규모 서비스에서는 서버 페이지네이션·지리 쿼리·집계 캐시로 전환한다.

## 검증

일반 테스트: IP 정규화/게시글별 해시/신뢰 헤더/주변 반경·정렬·공개 범위.
에뮬레이터: 동시 동일 IP 요청 중복 방지, 다른 IP 집계, 좋아요 취소/재시도, 비공개 글 거부, 비Google 가입·업로드 거부, 집계와 표 직접 조작/조회 거부.
브라우저: 리스트 정렬 선택, 준비 중 안내, 위치 동의 팝업, 미동의 후 전체보기.
실제 이용자의 현재 위치 권한과 운영 Firebase 좋아요 저장은 실행하지 않았다.

참고: [Firebase Admin SDK 설정](https://firebase.google.com/docs/admin/setup), [Vercel 요청 헤더](https://vercel.com/docs/headers/request-headers).
